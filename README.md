# АРМ захвата legacy-страниц Реестра 35

Локальное приложение принимает URL вида `https://<company>.reestr35.ru/`, снимает содержательные сегменты страницы в PNG и проводит потоковую визуальную QA-проверку. Исполняемый backend, helper `capture.cjs` и QA-конфигурация находятся в `src/`; интерфейс — в `public/`, тесты — в `test/`. Исходный skill и прежний workspace не нужны.

## Готовая версия для Windows x64

Скачайте `Reestr35-ARM-v3.2.0-win-x64.zip` из GitHub Releases, распакуйте архив целиком и запустите `Reestr35 ARM.exe`. Приложение откроется в браузере по умолчанию; повторный запуск EXE откроет уже работающий АРМ. Консоль не появляется. Завершайте работу кнопкой отключения в интерфейсе: закрытие вкладки браузера не выключает backend.

Node.js 24.21.0, Playwright 1.62.1 и sharp 0.35.4 включены в `runtime/`. Отдельно нужны установленный Chrome и `codex.exe` с выполненным входом в Codex. Launcher проверяет Chrome и ищет Codex по `ARM_CODEX_EXE`, затем в PATH, затем в последней установленной версии `%LOCALAPPDATA%\OpenAI\Codex\bin\*\codex.exe`; выбранные пути пишет в журнал. При отсутствии зависимости запуск прекращается с понятной ошибкой. Данные и журналы portable-версии сохраняются в `%LOCALAPPDATA%\Reestr35 ARM`; перенос папки приложения не переносит и не удаляет эти данные. При ошибке запуска EXE показывает окно с путём к журналу.

EXE не подписан цифровой подписью (unsigned), поэтому Windows SmartScreen может показать предупреждение. Единственный asset релиза — ZIP; его SHA256 опубликован в описании релиза. В корне распакованного пакета находятся только EXE, `src/`, `public/` и `runtime/`; лицензии зависимостей сохранены внутри `runtime/`, дополнительные тексты LGPL-3.0, GPL-3.0 и MPL-2.0 с notice sharp/libvips — в `runtime/licenses/`.

## Запуск из исходников

Требуются:

- Windows и PowerShell;
- Node.js 24.21.0+;
- Chrome;
- доступные Node-модули `playwright` и `sharp`;
- `codex.exe` и выполненный вход в Codex.

Из корня `reestr35-legacy-migration-arm`:

```powershell
./start.ps1
```

Затем откройте <http://127.0.0.1:4318>.

Пример с другим портом, лимитом параллельности и внешним каталогом данных:

```powershell
./start.ps1 -Port 4319 -Concurrency 1 -DataDir 'D:\Reestr35\arm-data'
```

`start.ps1` использует локальные зависимости после `npm ci` либо существующий bundled runtime Codex, проверяет зависимости и сохраняет журнал backend в `<ARM_DATA_DIR>/logs/`, создавая этот каталог при необходимости. При установке задайте `$env:PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD='1'`: захват использует установленный Chrome. `npm start` и `node src/server.cjs` тоже поддерживаются, если Node-окружение уже настроено. Все варианты запуска работают из произвольного текущего каталога: пути приложения вычисляются от корня АРМа, а не от `process.cwd()`.

Для сборки нужен Go 1.27.1 и PowerShell 7: `./build/build-release.ps1`. При более старом установленном Go можно задать `$env:GOTOOLCHAIN='go1.27.1'`, чтобы Go скачал закреплённый compiler. Скрипт скачивает Node по закреплённому SHA256, устанавливает production-зависимости через `npm ci`, создаёт Windows GUI EXE с иконкой/версией и ZIP с фиксированными временами файлов. Tag workflow `.github/workflows/release.yml` проверяет исходники, извлечённый пакет и публикует только ZIP, добавляя SHA256 к release notes. Проверки пакета: `node build/validate-package.cjs <папка-пакета>` и `node build/smoke-package.cjs <папка-пакета>`.

### Параметры

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `ARM_DATA_DIR` | `local/` | Корень локальных данных; относительный путь считается от корня АРМа |
| `ARM_PORT` | `4318` | Локальный HTTP-порт |
| `ARM_CONCURRENCY` | `2` | Общий лимит capture и QA, от 1 до 8 |
| `ARM_CODEX_EXE` | `codex` | Путь к Codex CLI |
| `ARM_IDLE_TIMEOUT_MS` | `600000` | Таймаут простоя после готового capture/manifest |

Если в `state.json` уже сохранена concurrency, она имеет приоритет над стартовым fallback. Изменить лимит во время работы можно в интерфейсе или через `POST /api/settings` с JSON `{ "concurrency": 1 }`.

## Локальные данные

При первом запуске АРМ сам создаёт `local/`. Если каталога нет, очередь стартует с чистым состоянием. Каталог исключён из Git через `.gitignore`.

```text
local/
├─ state.json                 # очередь, попытки, статусы и concurrency
├─ page-builder/              # отдельный JSON шага 3 для каждой компании
├─ server.lock                # защита от второго backend
├─ runs/                     # capture, manifests, QA-checkpoints и итоги
├─ logs/
│  └─ server-*.log           # журналы start.ps1
├─ qa-staging/               # проверенные копии PNG для QA
├─ qa-servers/               # рабочие cwd app-server
├─ tmp/                      # временные файлы Node/Playwright
├─ test-output/              # артефакты тестов
└─ test-temp/                # временные тестовые каталоги
```

Каждая попытка хранится в `local/runs/<job-id>/attempt-NNN/`. Старые попытки не перезаписываются. JSON состояния, manifest, QA-progress и результата записываются атомарно через временный файл и rename. Повреждённый `state.json` не сбрасывается молча.

## Как работает попытка

### Архитектура обработки страницы

Обработка разделена на три уровня:

- `src/pipeline/queue.cjs` — общий жизненный цикл страницы: задания и попытки, сохранение state, FIFO, concurrency, остановка и snapshot. `pipeline/registry.cjs` подключает workflow с capture/QA и HTML/медиа.
- `src/stages/capture-qa/index.cjs` — координатор этапа capture + QA: восстановление, переходы между операциями, целостность результата и правила повторной QA.
- `stages/capture-qa/capture/` — capture helper, запуск, inventory/coverage и immutable manifest; `stages/capture-qa/qa/` — отдельный запуск QA, policy, checkpoints, staging и app-server.

HTTP/SSE и защита запросов находятся в `src/http/server.cjs`; файловые, runtime и process helpers — в `src/infrastructure/`. Старые `src/server.cjs`, `capture.cjs`, `launcher.cjs`, `lib.cjs`, `qa.cjs` и `app-server.cjs` сохраняют CLI/CommonJS-интерфейсы. Legacy v1 helpers вынесены в `src/compat/`.

Очередь получает этап через `stageFactory`. Этап задаёт начальные поля попытки, восстановление и проекцию, выбирает следующую операцию в `start(job, attempt)` и сообщает о занятых восстановленными процессами слотах. Каждый runner регистрирует процесс в общем `active`, предоставляет `armInterrupt()` и освобождает слот только после подтверждённого завершения. Переход `afterCapture` ставит QA в хвост общей FIFO-очереди: capture и QA занимают отдельные слоты. Runners используют контекст очереди для сохранения state и уведомлений, а coordinator определяет результат этапа.

`state.json` остаётся версии 2. `pipeline/registry.cjs` подключает `stages/workflow.cjs`: capture/QA и второй этап `stages/html-media/`. Успешный capture/QA сохраняет `captureStatus: complete`, затем попытка переходит в `phase: html-media`, `status: paused`. При загрузке прежние успешные попытки workflow 2 проходят тот же переход. Это не запускает скачивание: нажмите «Продолжить» в очереди или во втором этапе. Manifest и checkpoints первого этапа остаются неизменными; их целостность продолжает проверяться.

### HTML и медиа

Приложение содержит `src/resources/domains.json` и 92 исходных HTML в `src/resources/html/<hostname>.html`. `import-report.json` фиксирует SHA256, 33 домена без HTML и 3 HTML без домена; для них соответствия не угадывались. Источники импортированы из согласованной выгрузки `domains.json` + `todo/paid`. Повторный явный импорт для разработчика: `node build/import-html.cjs <domains.json> <paid-directory> src/resources`. Portable-сборка копирует весь `src/`; доступ к прежнему workspace во время работы не нужен.

Для каждой попытки HTML копируется byte-for-byte в `runs/<job>/attempt-NNN/html-media/revision-NNN/source.html`. Рядом находятся атомарный `manifest.json` и `objects/<sha256>`. Источник revision неизменяем; ручная замена создаёт следующую revision и сохраняет прежнюю на диске. Номер revision не показывается в подписи карточки. При отсутствии/ошибке HTML нажатие карточки открывает выбор файла. Загрузка ограничена 8 MiB, защищена Origin/CSRF и номером попытки/revision; после неё требуется «Продолжить» в общем статусе очереди. Continue/Pause не дублируются в содержимом этапа.

HTML modal использует настоящий CodeMirror 6 read-only/non-editable: светлая тема, подсветка HTML, номера строк и folding gutter без поиска; прокручивается только содержимое редактора, а не внешний контейнер modal. Prettier 3.9.6 HTML parser форматирует только копию для просмотра; при ошибке показаны raw text и предупреждение. JSON modal использует vanilla-jsoneditor 3.13.0 как одно read-only дерево со сворачиванием узлов, без переключателя режима, поиска, меню, navigation/status bars и toolbar; встроенные Ctrl/Cmd+F и Ctrl/Cmd+H блокируются только внутри viewer. Editors уничтожаются при закрытии/новом запросе, асинхронный formatter не может восстановить закрытый viewer. HTML/scripts не исполняются; скачивание сохраняет исходные bytes.

Offline browser bundle создаётся `npm run build:editors` после `npm ci`; `npm run check:editors` и тест сравнивают воспроизводимую сборку с сохранёнными файлами. Release build устанавливает pinned devDependencies и отказывает при stale bundle. `public/vendor/editors/manifest.json` фиксирует версии, source/output SHA и лицензии всех включённых компонентов; package validation повторяет проверку. JSONEditor уже содержит некоторые upstream-компоненты: они определяются по published sourcemap; для них отдельно указана версия pinned license-source, не выдаваемая за внутреннюю версию upstream bundle. Полные licenses/Prettier third-party notices входят в portable, runtime npm/CDN/imports не нужны.

В заголовках HTML, JSON и PNG/image modal находятся компактные кнопки копирования и скачивания перед закрытием. Текст копируется в показанном виде, скачивается исходный файл; raster копируется через ClipboardItem (при необходимости преобразуется в PNG). После успеха цвет остаётся нейтральным, подтверждение доступно aria-live; ошибки остаются видимыми. QA-статус PNG показан только компактным кругом в углу thumbnail, не в modal; текст доступен через tooltip и accessible label. Оба image modal имеют title/counter в строке, Previous/Next и стрелки; возвращают фокус исходной карточке даже после polling. Обе галереи используют одинаковые размеры, padding, object-fit и responsive columns, без captions под изображениями.

parse5 разбирает HTML без выполнения JavaScript. Inventory включает img/src, srcset, ссылки на изображения/документы/архивы, CSS url(), video/audio/source, poster, iframe, embed/object. Относительные URL считаются от URL задания, а не от `<base>`; это предположение записано в provenance. Скрипты, обработчики событий, lazy data-src, Flash, data/blob/file/javascript и CSS URL с escape отмечаются unsupported. Внешние iframe/страницы embed сохраняются как ссылки; видео со страниц не извлекается. Тексты распознаются как UTF-8 либо по объявленному charset; исходные байты не преобразуются.

Ссылки с расширением в атрибуте `download` тоже входят в inventory (например, `/download?id=4` + `download="manual.pdf"`); имя сохраняется в occurrence. Для raster MIME проверяются сигнатуры, включая BMP file/DIB header и AVIF ftyp/brands. Неизвестные `application/x-*`, Flash MIME и неподтверждённые бинарные payload отклоняются. `application/octet-stream` принимается только при узнаваемой сигнатуре поддерживаемого формата.

Каждый ресурс содержит исходный/resolved URL, occurrence, redirect chain/final URL, MIME, bytes, SHA256, object или причину ошибки. Частичные ошибки дают `htmlMedia.status: ready_with_issues` и общий `status: complete`, сохраняя успешные объекты. Прогресс в state содержит только счётчики; полный inventory запрашивается отдельно. Шаги открываются последовательно: успешный capture+QA → HTML и медиа → после завершения второго этапа «Новая страница». Отдельного шага 4 нет.

### Новая страница

Шаг 3 показывает общую часть и вкладки с блоками типов banner, text, buttons, image, gallery, table и video. Начальный шаблон детерминированно строится из bundled `src/resources/html/mori-cinema.reestr35.ru.html`; SHA-256 этого источника хранится в document. Превью медиа рендерятся локально; браузер не запрашивает legacy URL.

Данные хранятся в `<ARM_DATA_DIR>/page-builder/<job-id>.json` отдельно от `state.json` v2. Запись атомарная; API `GET/POST /api/page-builder/<job-id>` валидирует схему, ограничивает строки/количество узлов и использует `revision` для compare-and-swap. POST проходит те же проверки Host/Origin/CSRF/Fetch Metadata, что и остальные мутации АРМа. Каждый блок имеет статус `unreviewed`, `passed` или `failed`; для `failed` причина обязательна. Статусы общей части, вкладок и страницы вычисляются только из входящих в них блоков. Компактный индикатор шага 3 в заголовке показывает проверенные блоки и их распределение; непройденная визуальная проверка остаётся жёлтой, а красный зарезервирован для системной ошибки.

Пауза ожидает завершения текущего файла и атомарного checkpoint. После перезапуска backend активный второй этап становится paused; продолжение проверяет SHA256 источника/готовых объектов и не скачивает их повторно. Shutdown прерывает сетевой запрос, удаляет временный файл и сохраняет последний checkpoint. Неподтверждённый файл после аварии может скачаться повторно. Замена HTML и retry запрещены во время работающего worker/загрузки; retry по-прежнему создаёт новую попытку capture.

Скачиваются только HTTP(S) ресурсы без credentials. Каждый redirect проходит повторную проверку всех DNS-адресов; соединение закрепляется за проверенным IP. Запрещены private, loopback, link-local, metadata, multicast и прочие непубличные диапазоны. Лимиты: 3000 occurrences (крупнейший bundled HTML содержит 2740), 32 MiB на файл, 256 MiB на revision включая ошибочные передачи, 30 секунд на ресурс, 5 redirects. Проверяются MIME и сигнатуры распространённых форматов; HTML/script-ответы отклоняются. SVG и документы выдаются только как attachment/octet-stream с sandbox CSP; inline разрешены проверенные растровые изображения. HTML никогда не выдаётся активным документом на origin приложения.

### Выполнение

1. Backend нормализует URL и ставит capture в FIFO-очередь.
2. Trusted `src/launcher.cjs` запускает локальный `src/capture.cjs` без shell. После каждого готового PNG (и доказанного absent) helper атомарно сохраняет `capture-checkpoint.json`: identity попытки, полный план, завершённый префикс, размеры, bytes и SHA-256. PNG сначала собирается во временный файл, затем публикуется целиком.
3. Backend проверяет `capture-report.json` и все PNG, затем фиксирует immutable `capture-manifest.json` с размерами, SHA-256 и полным inventory layout/root/groups/segments, включая absent-сегменты и проблемные diagnostics.
4. Для QA-прохода компании создаётся отдельный одноразовый `codex app-server`.
5. Все ещё не проверенные PNG передаются в одном ephemeral turn. Единственный QA-инструмент `record_review` принимает результат по одному PNG.
6. Каждый принятый вызов сразу сохраняет checkpoint в `qa-progress.json`; после сбоя проверяется только остаток.
7. Итог вычисляет backend по manifest и checkpoints. Текстовый ответ модели сам по себе не подтверждает QA.

Галерея показывает только PNG из capture report. Перед QA и каждым checkpoint backend повторно проверяет manifest, пути, PNG signature/IHDR, размеры относительно segment.png/box и SHA-256. Независимый coverage gate сверяет модель вкладок, все ожидаемые семантические сегменты и реальные PNG: без пропусков, дублей, лишних файлов и неверных цепочек; пустая вкладка требует PNG, absent допустим только для доказанно пустого tail/footer. Копии для QA стейджатся внутри каталога данных и сверяются по SHA-256.

QA policy v5 имеет отдельные version/hash, не входящие в identity capture. При смене policy старые checkpoints остаются историей, но все PNG требуют новой проверки; immutable manifest и его hash не переписываются. Каждый проход, включая остаток, получает полный inventory и визуальный checklist. QA оценивает доказуемые дефекты захвата, а не исходный дизайн или читаемость текста внутри загруженных изображений. Технически чистые пустые вкладки допустимы. Касание края PNG, незамкнутая рамка или исходный clipping сами по себе не доказывают обрезку: при clean status/coverage/diagnostics QA доверяет рассчитанной semantic box. Реальные unloaded/placeholder/failed iframe, швы/повторы сборки и неверная активная вкладка остаются дефектами. Header заканчивается перед первой строкой/списком кнопок вкладок (`ul.tabs`), а не перед общим контейнером `main_block`/tbody. Предшествующие заголовок секции, рамка, legend и стрелка принадлежат header и при чистых status/coverage/diagnostics не являются wrong boundary. Сама кнопочная панель и её содержимое в header не входят; неверная содержательная панель и дублированный контент остаются дефектами.

## Статусы

| Статус | Подпись, цвет, значок | Действие статуса |
| --- | --- | --- |
| `paused` | На паузе, серый, пауза | Продолжить текущий capture/QA либо HTML и медиа после проверки checkpoints |
| `queued` | В очереди, синий, часы | Приостановить немедленно (capture и QA) |
| `running` | Выполняется, синий, анимация | Приостановить capture с сохранением прогресса |
| `validating` | Проверяется, синий, анимация; в результате azure badge | Приостановить QA с сохранением принятых checkpoints |
| `pausing` | Приостанавливается, жёлтый, анимация | Недоступно до фактического завершения операции |
| `complete` | Готово, зелёный, галочка | Перезапустить |
| `needs_review` | Нужна проверка, красный, предупреждение; в результате жёлтый badge | Перезапустить |
| `failed` | Ошибка, красный, предупреждение | Перезапустить |
| `interrupted` | Прервано, красный, предупреждение | Продолжить при пригодном checkpoint, иначе Перезапустить |
| `incomplete` (совместимость) | Неполный результат, оранжевый, предупреждение | Перезапустить с сохранением истории |
| `cancelled` (совместимость) | Отменено, серый, квадрат | Перезапустить с сохранением истории |

Строка очереди во всех состояниях открывает результат. «Перезапустить» в статусе и в результатах вызывает существующий `retry`: создаёт новую попытку и сохраняет историю. Доступно после завершения или паузы и подтверждённого завершения прежнего процесса. Подсказка индикатора всегда содержит статус и одно действие: «Продолжить», «Приостановить», «Перезапустить» или «Недоступно». При отсутствии действия индикатор не кликается и не бледнеет, подсказка доступна при наведении. Пользовательский `stop` и его HTTP endpoint удалены; внутренняя остановка остаётся для shutdown и ошибок. Старый endpoint `continue-qa` сохранён для совместимости.

Пауза capture переводит `running → pausing`, дожидается конца текущего сегмента, атомарного checkpoint и закрытия worker, затем устанавливает `paused`. При возобновлении в той же попытке проверяются identity/checksum checkpoint, полный план, порядок, состав PNG, размеры и SHA-256; после загрузки страницы заново сверяется её структура и план. Готовые PNG не переснимаются, работа продолжается с первого незавершённого сегмента. Несовпадение блокирует продолжение без перезаписи старых артефактов. Legacy capture без checkpoint возобновить нельзя; доступно «Перезапустить».

Пауза QA сохраняет уже принятые checkpoints и останавливает выделенный app-server. Возобновление в новой QA-сессии получает только оставшиеся PNG текущей policy. Поздние ответы прежней сессии не принимаются. Пауза не запускает автоматический retry.

Аварийное завершение между публикацией PNG и checkpoint может оставить неучтённый PNG: такое состояние блокируется, требуется новая попытка. Незавершённый временный PNG не считается результатом. Пауза длинного сегмента ожидает его завершения; при ошибке сохраняется последний принятый checkpoint.

Ошибка внутри незавершённого сегмента сохраняет фазу capture и статус `interrupted`, даже если пауза не запрашивалась. При валидном checkpoint возобновление продолжает эту же попытку с незавершённого сегмента. QA начинается только после завершения всего плана; технические замечания у уже снятых PNG не мешают завершить capture и передать их на QA.

## Параллельность, остановка и восстановление

Общий лимит concurrency учитывает и capture, и QA. Каждый QA-проход занимает один слот до фактического закрытия его app-server. Повышение лимита сразу запускает следующие FIFO-задания; понижение не прерывает уже активные.

Закрытие браузера не останавливает backend. `Ctrl+C` останавливает активные задания, закрывает app-server и сохраняет очередь. Остановка одной компании не затрагивает другие.

Для capture и QA сохраняются launch token, generation, PID и lease. После restart backend не завершает чужой или неопределённый PID. Восстановление разрешается только по finished lease или после консервативной проверки смерти всех связанных процессов. Поздние события прежнего generation игнорируются.

После сбоя QA АРМ до трёх раз автоматически повторяет только непроверенный остаток. Отмена пользователем запрещает автопродолжение. Capture автоматически не перезапускается.

## Изоляция QA

QA запускается на `gpt-5.6-sol` с reasoning `medium` и читает только проверенные копии PNG. В его контексте нет project instructions, skills, memories, hooks, plugins, collaboration, shell, browser/computer tools, apps и image generation. Доступен только `record_review`; sandbox read-only, approval policy `never`.

Пользовательские MCP отключаются по имени после `config/read`: пустое `mcp_servers={}` не очищает объединённый конфиг. Реальный wire audit проверяет итоговый payload CLI: ровно один tool, никаких проектных инструкций и `detail: original` для PNG. После обновления Codex CLI этот audit нужно повторить.

## Безопасность и интерфейс

- Backend слушает только `127.0.0.1` и проверяет Host, Origin, CSRF и `sec-fetch-site`.
- Допускаются только HTTPS-адреса `*.reestr35.ru` без credentials и нестандартного порта; redirect обязан сохранить origin.
- File API отдаёт только PNG/report из manifest и фиксированные журналы, проверяя realpath против symlink/junction.
- Браузер не задаёт команды, модель, аргументы или пути.
- UI использует локальные vendor-файлы Tabler, CSP и `textContent`. Источники, хэши и лицензии лежат в `public/vendor/UPSTREAM.md`, `LICENSE` и `ICONS-LICENSE`.

Интерфейс показывает очередь, историю попыток, галерею, счётчики QA и журналы. SSE обновляет состояние сразу, polling остаётся fallback. Полные журналы хранятся на диске; UI показывает хвост до 128 KiB.

## Тесты

Полный набор:

```powershell
npm test
```

Целевые наборы:

| Команда | Что проверяет |
| --- | --- |
| `npm run test:backend` | Очередь, manifest, checkpoints, stop/recovery и API |
| `npm run test:html-media` | Импорт, migration, статический inventory, SSRF/лимиты, upload, pause/resume, API и браузерный UI второго этапа |
| `npm run test:ui` | Интерфейс и браузерные сценарии |
| `npm run test:capture` | Самостоятельный capture helper |
| `npm run test:portability` | `local/`, `ARM_DATA_DIR`, чужая cwd и перенос данных |
| `npm run test:cli` | Wire audit установленного Codex CLI |

Все npm test-команды идут через `test/run.cjs`. Runner находит Node с нужными модулями и до старта test workers направляет `TMP`, `TEMP` и `TMPDIR` в `<ARM_DATA_DIR>/tmp`. Тесты не меняют рабочие `runs`, `state.json` и `server.lock`.

Wire audit использует локальный mock `/responses`, не вызывает реальную модель и не запускает инструменты:

```powershell
$env:ARM_TEST_CODEX_EXE = (Get-Command codex).Source
npm run test:cli
```

Без `ARM_TEST_CODEX_EXE` wire audit пропускается.
